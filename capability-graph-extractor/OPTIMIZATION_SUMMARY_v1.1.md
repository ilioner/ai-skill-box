# Capability-Graph-Extractor Skill 优化总结 v1.1

## 优化背景

基于《大学生心理健康》课程能力图谱提取的完整实践，发现 Skill 在四个关键环节存在明显问题：

1. **可视化交付物体验差**：原脚本生成的 HTML 需要手动迭代多个版本才能达到可用状态
2. **标准验证流程不清晰**：实践中检索到国家标准但因网络受限未能完整验证，层次模糊
3. **根节点设计缺失**：初始图谱有 7 个模块级根节点，缺少统一的课程总入口
4. **孤立节点消除机制不明确**：v1.0 初始图谱有 12 个孤立节点（34.3%），需要手动补充关系

用户明确指出：**本 Skill 是通用 Skill，不应针对某一具体课程（如心理健康课）进行过度定制**。优化方案必须抽象为跨课程适用的通用方法论。

## 完成的优化

### ✅ 优化 1：升级 `export_graph_html.py` 生成双版本可视化

**改进内容**：
- 自动生成 **graph_clean.html**（极简展示版）
  - 深色渐变背景 + 标题居中
  - 点击节点右侧滑出详情面板
  - 左下角固定显示创作依据
  - 完全响应式布局（支持手机视图）
  
- 自动生成 **graph_full.html**（完整分析版）
  - 节点/关系/孤立节点/根节点统计
  - 高亮孤立节点和根节点功能
  - 显示/隐藏关系标签
  - 完整的质量指标报告

**通用性**：适用于任何课程的能力图谱可视化，不绑定特定课程内容。

**文件位置**：`scripts/export_graph_html.py`

---

### ✅ 优化 2：在 `standards-acquisition.md` 明确标准验证三层次

**改进内容**：
- **Level 1：标准发现**（必须完成）
  - 检索到标题、发布机构、发文号、来源链接
  
- **Level 2：政策方向一致性**（最低要求）
  - 确认培养目标方向对齐，无明显冲突
  
- **Level 3：逐条对照验证**（理想状态）
  - 下载完整文件，逐条对照能力节点与上位标准条款

**通用性**：适用于所有课程的标准验证工作，明确不同验证深度的要求和限制。

**关键原则**：
- 必须诚实披露完成了哪个层次
- 不要模糊表述为"已验证"或"符合标准"
- 网络受限时可能无法完成 Level 3

**文件位置**：`references/standards-acquisition.md` 第 86-120 行

### ✅ 优化 3：在 `extraction-method.md` 补充根节点设计指导

**改进内容**：
新增"## 根节点设计"章节，包含：

1. **根节点的作用**：
   - Level 0 课程总根节点代表课程核心培养目标
   - 为多模块课程提供统一入口
   - 类型为 `course_goal`

2. **检测多根情况**：
   ```bash
   python scripts/validate_graph.py output/graph.json --connectivity
   ```

3. **创建总根节点**：
   - 从课程标准/教学大纲中提取课程总目标
   - 使用 `part_of` 包容关系连接到各模块根节点

4. **验证连通性**：
   - 根节点数应 ≤ 1
   - 连通节点占比应 ≥ 95%

**通用性**：适用于任何多模块课程，不预设具体模块数量或内容。

**文件位置**：`references/extraction-method.md` 第 195-248 行

---

### ✅ 优化 4：在 `extraction-method.md` 补充孤立节点预防机制

**改进内容**：
新增"## 孤立节点预防"章节，包含：

1. **三种常见孤立类型**：
   - 素质节点孤立（未建立作为能力培养目标的包容关系）
   - 模块内能力未建立关系
   - 跨模块能力未连接

2. **提取阶段检查清单**：
   - 识别孤立节点 → 分析原因 → 补充关系 → 验证连通性

3. **必须报告的指标**：
   - 孤立节点数量和 ID 列表
   - 每个孤立节点的分析
   - 建议的关系补充方案
   - 最终连通性指标

**通用性**：适用于任何课程图谱，不预设具体节点类型或关系模式。

**文件位置**：`references/extraction-method.md` 第 250-296 行

### ✅ 优化 5：在 `validate_graph.py` 添加根节点和孤立节点检测

**改进内容**：
1. 新增 `analyze_connectivity()` 函数：
   - 统计总节点/总关系/连通节点/连通比例
   - 识别根节点（无入边）
   - 识别孤立节点（无边）
   - 识别叶子节点（无出边）

2. 自动警告机制：
   - ⚠️ 无根节点（所有节点都有入边）
   - ⚠️ 多根节点（建议添加 Level 0 总根）
   - ⚠️ 孤立节点（提供 ID 列表）

3. 新增 `--connectivity` 参数：
   ```bash
   python scripts/validate_graph.py output/graph.json --connectivity
   ```

**通用性**：纯结构化图分析，不绑定任何课程内容。

**文件位置**：`scripts/validate_graph.py`

## 使用建议

### 对于 Skill 维护者

1. **持续验证通用性**：
   - 在其他课程（职业课、专业课）中测试方法论
   - 确保不引入课程特定的硬编码逻辑
   - 保持"方法 + 边界"而非"内容 + 规则"的设计

2. **补充案例研究**：
   - 建议在 `examples/case-studies/` 下补充 2-3 个不同类型课程的完整案例
   - 展示方法论在不同课程范式下的适用性

3. **脚本独立性**：
   - 保持脚本只做确定性处理（清单、校验、导出）
   - 不在脚本中内置第二套 LLM 调用
   - 不用关键词规则代替语义理解

### 对于 Skill 使用者

1. **小型课程（< 30 节点）**：
   - 阅读 README "最小化工作流"章节
   - 手工完成即可，无需安装 Python 或运行脚本

2. **中大型课程（≥ 50 节点）**：
   - 阅读 README "标准工作流"章节
   - 使用脚本自动化清点、校验、导出

3. **首次使用**：
   - 先读 `SKILL.md` 理解核心分工
   - 再读 `references/extraction-method.md` 学习提取方法
   - 最后根据需要查阅其他参考文档

4. **遇到问题**：
   - 查阅 README "常见问题"章节
   - 使用 `validate_graph.py --connectivity` 自动诊断
   - 参考 `references/` 目录下的方法论文档
