# Capability Graph Extractor

把分散的课程材料转化为**有来源、可审核、可更新**的课程能力图谱。默认同时处理四类核心节点：

- 能力：学习者最终能够完成什么。
- 知识：完成能力所需知道、理解什么。
- 思政/素养：完成任务时体现什么价值、态度、规范或职业品质。
- 问题：通过什么问题促进理解、应用、迁移与反思。

能力图谱不是教材目录的改写，也不是模型补齐出来的“理想课程”。正式结论必须能够回到资料原文、外部正式标准或明确标注的推断理由。

## 核心分工

### 宿主模型负责

- 理解文件内容、课程性质和适用情境。
- 区分能力、知识、素养、问题、活动、资源和评价证据。
- 从多份资料中归纳同义节点、层级和关系。
- 判断哪些内容是原文提取、语义归纳、推断或新增建议。
- 解释冲突、缺口、课程边界和关系成立理由。

### 本 Skill 负责

- 规定材料清点、证据保存、抽取、关联、审核和交付流程。
- 规定通用输出结构及最低质量门槛。
- 提供课程范式、残缺资料处理和安全边界方法。
- 提供确定性脚本：文件清单、稳定 ID、JSON 校验、CSV/Mermaid 导出。

### 脚本不得负责

- 不调用第二套大模型或绑定 API Key。
- 不用关键词规则代替课程理解。
- 不预设某门课程必须包含哪些能力或多少节点。
- 不把“了解/熟悉”机械改写为材料未支持的高阶能力。
- 不把推断或用户采纳的建议伪装成原始资料事实。

## 何时使用

出现以下任务时使用：

- 从一个课程资料目录提炼能力图谱或四图谱。
- 分析课程标准、教案、PPT、教材中的能力要求。
- 建立能力—知识—任务—资源—评价的追溯关系。
- 检查课程目标、教学活动和评价是否形成闭环。
- 资料不完整，但仍需形成带缺口说明的候选图谱。

只需做通用实体关系抽取、且不涉及课程能力设计时，优先使用普通知识图谱抽取工具。

## 工作原则

1. **先清点，后理解**：先形成材料清单，不凭文件名认定文件权威性。
2. **先证据，后节点**：每个正式节点保存来源原文和定位；无法定位时明确说明。
3. **能力不是章节名**：能力应描述学习者在一定条件下可完成的行动。
4. **不虚构完整性**：缺任务书、课标或评价材料时保留缺口，不擅自补成既有事实。
5. **标准与实施分开**：课程标准/正式标准界定目标；教案/PPT证明实际教了什么。
6. **关系也要可解释**：前置、支撑、包容等关系必须有来源或推断理由。
7. **建议与事实分层**：模型提出的完善建议单独进入候选区，待人工确认。
8. **人工拥有发布权**：模型产出默认为草稿或待审核，除非用户明确完成审核。

## 快速流程

### 1. 建立工作目录

建议输出：

```text
output/
├── material_inventory.json
├── source_extracts/
├── graph.draft.json
├── review_issues.json
├── graph.reviewed.json
├── nodes.csv
├── relations.csv
└── graph.mmd
```

不要覆盖原始材料。

### 2. 扫描并清点资料

可运行：

```bash
python scripts/inventory_materials.py <资料目录> --output output/material_inventory.json
```

然后由宿主模型逐项判断：

- 实际文件类型与可读性。
- 可能角色：国家/行业标准、学校课程标准、授课计划、教案、课件、教材、任务书、量规、其他。
- 权威性、适用性、时效性。
- 是否需要 OCR、视觉识别或外部检索。

扫描脚本只按扩展名和路径做机械清点，不能替代上述判断。

### 3. 判断课程范式

读取 `references/course-paradigms.md`。

- 职业教育专业课通常采用：岗位/职业活动 → 典型工作任务 → 工作过程 → 综合职业能力 → 课程任务。
- 公共基础课通常采用：课程育人要求/学生发展任务 → 典型学习生活情境 → 可迁移能力 → 学习活动。
- 其他课程可组合或提出新范式，但要说明理由，不能强套岗位逻辑。

### 4. 建立标准基线

读取 `references/standards-acquisition.md`。

按以下顺序形成基线，而不是简单“从网上找答案”：

1. 用户材料中的正式标准和课程文件。
2. 缺失或需校验时，检索适用于当前课程的官方/权威标准。
3. 内置方法参考只用于结构、术语和审核，不冒充课程正式标准。

记录每份标准的标题、发布机构、版本/日期、适用范围、来源位置、有效性状态和采用理由。不同来源冲突时，不自动覆盖；记录冲突并按权威性、适用性、时效性综合判断，必要时请用户或课程负责人裁决。

### 5. 分块读取并建立来源摘录

根据宿主可用工具读取 Word、PDF、PPT、Excel、图片或网页。保持以下最小来源记录：

```json
{
  "source_id": "SRC-...",
  "file": "相对路径",
  "location": "页码/幻灯片/章节/表格/段落",
  "quote": "与节点或关系直接相关的原文",
  "context": "必要上下文",
  "read_status": "complete|partial|unreadable",
  "notes": "OCR、缺页、解析失败等说明"
}
```

若工具不能读取扫描页、音视频或复杂图表，报告未覆盖范围；不得声称全量解析。

### 6. 提取候选节点

读取 `references/extraction-method.md` 和 `references/four-graphs-relations.md`。

逐块提取：

- 明确写出的课程目标和能力要求。
- 从任务、操作、案例、练习和评价中可合理归纳的能力候选。
- 支撑知识、思政/素养、驱动问题。
- 教学项目、学习任务、活动、资源、评价证据。

每项标注 `evidence_kind`：

- `quoted`：原文明确表达。
- `synthesized`：多处原文的保守语义归纳。
- `inferred`：根据任务或活动推断，必须写理由。
- `proposed`：为完善课程新增的建议，不属于原始资料事实。

不得给这些类别附未经验证的固定可信度百分比。

### 7. 规范化能力表述

优先使用：

> 行为动词 + 操作对象 + 必要条件/方法/工具/规范 + 可选质量要求

示例：

- 弱：了解沟通技巧。
- 较好：能在模拟同伴冲突情境中，运用倾听和“我信息”表达完成沟通，并说明策略选择理由。

规范化必须保持证据边界。如果材料只支持“识别”，不能提升成“独立解决复杂问题”。能力分级没有跨课程统一答案；L1—L4 只能在项目明确选用并定义后使用。

### 8. 合并、分层并建立关系

常用关系见 `references/four-graphs-relations.md`。至少考虑：

- `requires_knowledge`：能力需要知识。
- `depends_on`：能力存在前置依赖。
- `part_of`：下位能力属于上位能力。
- `develops_quality`：能力活动发展某项素养。
- `driven_by_question`：问题驱动能力形成。
- `practiced_in`：能力在任务/活动中练习。
- `supported_by_resource`：资源支持节点学习。
- `assessed_by`：评价证据观察该能力。
- `derived_from`：节点来源于标准、任务或情境。

关系必须记录来源或推断理由。不要为了图谱连通而制造关系。

### 9. 处理残缺资料

读取 `references/incomplete-materials.md`。

最低输入可以是课程名加至少一份可读教学内容，但输出状态必须随证据变化：

- 只有课程名：属于“框架设计”，不是资料抽取。
- 只有课件/教案：可逆向提取候选能力，但不能宣称符合本校正式课标。
- 只有标准/计划：可建立目标框架，但活动、资源、评价关系标为缺失。
- 材料部分齐全：采用混合模式，已证实内容与建议补全分开。
- 材料齐全：仍需检查文件版本、矛盾和实施偏差。

外部标准用于约束、校验或候选补充，不能偷偷填进“用户材料原文”。

### 10. 安全与伦理检查

对于心理健康、医疗、法律、安全生产等敏感课程，检查普通学习者的职责边界。

以大学生心理健康公共课为例：

- 可培养自助、有限互助、风险信号识别、求助与转介意识。
- 不要求普通学生诊断心理疾病、实施治疗或独立处置危机。
- 不根据心理测评结果或人格特征给学习成绩。
- 不强迫披露创伤、疾病或其他敏感经历。

具体课程边界必须以适用正式标准和专业人员审核为准，不把该示例硬编码到其他课程。

### 11. 生成草稿并确定性校验

按照 `templates/graph.schema.json` 生成 `graph.draft.json`。可运行：

```bash
python scripts/assign_ids.py output/graph.draft.json --write
python scripts/validate_graph.py output/graph.draft.json --schema templates/graph.schema.json
```

校验脚本只检查：JSON 结构、必填字段、ID 唯一性、关系端点、来源引用、枚举值等。它不会判断教学内容是否专业正确。

### 12. 人工审核与发布

读取 `references/evidence-review.md`，输出 `review_issues.json`，至少列出：

- 标准冲突和版本问题。
- 无来源或定位不足的节点。
- 推断/建议节点及理由。
- 有能力无任务、无资源或无评价证据的缺口。
- 关系方向或层级争议。
- 专业、安全和伦理风险。
- 未读取或解析不完整的材料。

由课程负责人、专业教师或相关专家确认后，把节点 `review_status` 更新为 `accepted|rejected|revised`，并保存审核人、日期和说明。不要覆盖草稿文件。

### 13. 导出交付物

```bash
python scripts/export_graph.py output/graph.reviewed.json --out-dir output/export --formats csv,mermaid,html
```

支持的格式：
- `csv`：节点和关系列表，可导入 Excel 或数据库
- `mermaid`：Mermaid 图谱代码，可嵌入文档或渲染为 SVG
- `html`：ECharts 交互式可视化网页（力引导布局），支持：
  - 按节点类型着色（能力/知识/素养/问题）
  - 悬停显示完整节点信息
  - 拖拽调整布局
  - 点击节点高亮相邻关系
  - 搜索定位节点
  - 离线可用（ECharts CDN 内联）

默认交付：

- 图谱 JSON。
- 节点和关系列表 CSV（`nodes.csv`, `relations.csv`, `sources.csv`）。
- Mermaid 概览（`graph.mmd`）。
- ECharts 交互式网页（`graph.html`，可直接在浏览器打开）。
- 材料清单、冲突/缺口/审核报告。
- 方法说明：课程范式、标准基线、未覆盖范围、人工确认状态。

数据库导入、交互式 HTML 或其他格式属于可选下游步骤，不应成为本 Skill 的运行前提。

## 输出质量门槛

正式交付前逐项确认：

- 每个正式能力节点有来源或清晰推断理由。
- 能力与知识没有混为一类。
- 能力表述可观察，但没有超出材料支持范围。
- 关系端点存在，方向合理，并有来源或理由。
- `quoted/synthesized/inferred/proposed` 没有混用。
- 外部标准与用户材料可区分。
- 未读取材料和证据缺口已披露。
- 图谱状态未被错误标记为“已审核”。
- **根节点设计合理**：多模块课程应有统一的 Level 0 总根节点。
- **孤立节点已消除**：所有节点至少有一条入边或出边,孤立节点数为 0。
- **连通性指标达标**：连通节点占比 ≥ 95%,根节点数 ≤ 1。

## 关键改进（v1.1）

本次优化解决了实践中发现的四个关键问题：

### 1. 可视化交付物升级

**问题**：原脚本生成的 HTML 体验差,需要手动迭代多个版本才能达到可用状态。

**解决方案**：
- 升级 `scripts/export_graph_html.py`,现在自动生成两个版本：
  - **graph_clean.html**：极简展示版,适合演示和分享
    - 深色渐变背景 + 标题居中
    - 点击节点右侧滑出详情面板
    - 左下角固定显示创作依据
    - 完全响应式布局（支持手机视图）
  - **graph_full.html**：完整分析版,包含统计和调试工具
    - 节点/关系/孤立节点/根节点统计
    - 高亮孤立节点和根节点功能
    - 显示/隐藏关系标签
    - 完整的质量指标报告

### 2. 标准验证流程明确化

**问题**：实践中检索到国家标准但因网络受限未能下载完整 PDF,验证层次不清晰。

**解决方案**：在 `references/standards-acquisition.md` 明确三个递进验证层次：
- **Level 1：标准发现**（必须完成）— 检索到标题、发布机构、发文号、来源链接
- **Level 2：政策方向一致性**（最低要求）— 确认培养目标方向对齐,无明显冲突
- **Level 3：逐条对照验证**（理想状态）— 下载完整文件,逐条对照能力节点与上位标准条款

输出时必须明确说明完成了哪个层次,不要模糊表述为"已验证"或"符合标准"。

### 3. 根节点设计指导

**问题**：实践中初始图谱有 7 个模块级根节点,缺少统一的课程总入口。

**解决方案**：在 `references/extraction-method.md` 补充"根节点设计"章节：
- 添加 **Level 0 课程总根节点**（类型 `course_goal`）代表课程核心培养目标
- 使用 `part_of` 包容关系连接总根节点到各模块根节点
- 提供检测多根情况、创建总根节点、建立包容关系、验证连通性的完整步骤

### 4. 孤立节点预防机制

**问题**：实践中 v1.0 初始图谱有 12 个孤立节点（34.3%）,需要手动补充关系。

**解决方案**：在 `references/extraction-method.md` 补充"孤立节点预防"章节：
- 识别三种常见孤立类型：素质节点孤立、模块内能力未建立关系、跨模块能力未连接
- 提供提取阶段检查清单：识别孤立节点 → 分析原因 → 补充关系 → 验证连通性
- 在提取报告中必须包含：孤立节点数量和 ID 列表、每个孤立节点的分析、建议的关系补充方案、最终连通性指标

### 5. 脚本增强

**升级 `scripts/validate_graph.py`**：
- 添加 `analyze_connectivity()` 函数分析图谱连通性
- 自动检测并警告多根节点和孤立节点
- 新增 `--connectivity` 参数显示详细连通性分析：
  - 总节点 / 总关系 / 连通节点 / 连通比例
  - 根节点数量和 ID 列表
  - 孤立节点数量和 ID 列表
  - 叶子节点数量

使用示例：
```bash
python scripts/validate_graph.py output/capability_graph.json --connectivity
```


- JSON 通过确定性校验脚本。

## 可迁移性要求

- 用“宿主可用的文档解析/搜索/网页工具”描述能力，不绑定某一 Agent 工具名。
- 所有路径相对于本 Skill 目录或用户工作目录，不写本机绝对路径。
- 无联网时只使用本地材料，并明确外部标准未在线核验。
- 无 OCR/视觉时标记扫描页或图片内容未解析。
- 无脚本执行环境时可人工遵循 schema，但不能声称已运行程序校验。
- 不依赖 Neo4j、向量数据库或特定模型供应商。
