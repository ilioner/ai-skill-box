# 能力图谱抽取方法

## 目标

把课程教学资料转成可审计的课程知识-能力-素养图谱。能力不是教材章节的改名，而是学生在明确情境中能够完成、能够被观察和评价的行动。

## 模型负责的判断

宿主 Agent 应逐份阅读材料并判断：

- 文件类型和证据用途：课程标准、授课计划、教案、任务书、教材、课件、评价材料或其他
- 课程性质和适用范式
- 能力、知识、素养、问题、活动、资源、评价的语义类别
- 能力的合并、拆分、上下位、前置和递进关系
- 事实、语义归纳、合理推断和新增建议的边界

不要用文件名、关键词或固定课程目录替代语义判断。

## 抽取顺序

1. 先清点文件并记录可读性、页码/段落/幻灯片定位。
2. 先建立课程标准基线；若没有课程标准，明确标记“缺少正式课程标准”，不能把教案或网络内容冒充正式目标。
3. 读取授课计划，确定学时、模块、任务和实施边界。
4. 读取教案、任务书、课件和教材，提取教学活动、情境、资源与评价证据。
5. 从原文目标中提取能力候选，再把章节名、知识名和活动名分别归类。
6. 对能力做教学化转写，但保留原文、转写理由和证据状态。
7. 建立关系，并为每条关系保存来源或推断理由。
8. 检查能力是否落到任务、活动、资源和评价；缺项输出缺口，不自动虚构。

## 能力表述

优先使用“学生能够……”表达，尽量包含：行为、对象、情境或条件、方法/工具、质量要求。避免单独使用“了解、掌握、熟悉、提高、培养”等不可观察表述。转写只能使隐含行动更清楚，不能凭空增加原资料没有的难度、课时或评价标准。

示例：

- 原文“了解情绪 ABC 理论”可提出候选“能在给定案例中使用 ABC 框架描述事件、信念与情绪后果”，但必须标为语义归纳/待审核，不能声称原文已有该完整能力。
- “掌握设备操作”不能直接扩写成具体设备、精度或时限，除非资料提供了这些条件。

## 层级

可选用课程自身的层级。没有明确层级时，可以提出 L1-L4 草案（识别理解、分析应用、综合解决、迁移改进），但必须标记为建议，不能作为跨课程统一标准。

## 三类能力

职业教育专业课可按专业能力、方法能力、社会能力组织；公共基础课可按课程实际目标分类，不强行套用岗位能力。心理健康等课程只能提取自助、有限互助、风险识别和专业求助相关能力，不把普通学生设定为诊断、治疗或危机处置者。

## 根节点设计

多模块课程常出现多个模块级根节点，缺少统一的课程总入口。建议添加 **Level 0 课程总根节点**以统一图谱结构：

### 设计原则

1. **课程总根节点（Level 0）**
   - 代表课程的核心培养目标，通常命名为“[课程名]素养”或“[课程名]综合能力”
   - 类型为 `course_goal`，区别于普通能力节点
   - 描述应来自课程标准的总体目标部分
   - 例：“大学生心理健康素养”、“职业英语综合应用能力”

2. **模块根节点（Level 1）**
   - 每个教学模块的核心能力，通常对应模块名称
   - 例：“情绪管理能力”、“商务函电写作能力”

3. **总根到模块根的关系**
   - 使用 `part_of` 包容关系：`{"source_id": "C000", "target_id": "C001", "relation_type": "part_of"}`
   - 表示模块能力是课程总目标的组成部分

### 添加总根节点的步骤

1. **检测多根情况**
   ```python
   # 找到所有没有入边的节点
   has_incoming = {rel['target_id'] for rel in relations}
   root_nodes = [n for n in nodes if n['id'] not in has_incoming]
   
   if len(root_nodes) > 1:
       print(f"⚠️  检测到 {len(root_nodes)} 个根节点，建议添加总根节点")
   ```

2. **创建总根节点**
   ```json
   {
     "id": "C000",
     "type": "course_goal",
     "name": "[课程名]素养",
     "level": 0,
     "description": "从课程标准总体目标提取",
     "module": "课程总目标",
     "source": "课程标准 - 总体目标",
     "confidence": "direct"
   }
   ```

3. **建立包容关系**
   ```json
   [
     {"source_id": "C000", "target_id": "C001", "relation_type": "part_of", "note": "模块 1 是总目标的组成部分"},
     {"source_id": "C000", "target_id": "C005", "relation_type": "part_of", "note": "模块 2 是总目标的组成部分"},
     ...
   ]
   ```

4. **验证连通性**
   ```python
   # 再次检查根节点数量
   has_incoming = {rel['target_id'] for rel in relations}
   root_nodes = [n for n in nodes if n['id'] not in has_incoming]
   
   if len(root_nodes) == 1:
       print(f"✅ 图谱已统一到单一根节点：{root_nodes[0]['name']}")
   ```

## 孤立节点预防

孤立节点（既无入边也无出边）会影响图谱的完整性和可用性。在提取阶段应主动预防：

### 常见孤立类型

1. **素质节点孤立**
   - 问题：素质目标（quality）被单独提取，未与能力培养建立关系
   - 解决：素质通常是能力培养的目标，应建立 `part_of` 包容关系
   - 例：`{"source_id": "[capability_id]", "target_id": "[quality_id]", "relation_type": "part_of"}`

2. **模块内部能力未建立关系**
   - 问题：同一模块内的多个能力没有前置或包容关系
   - 解决：分析模块内能力的逻辑顺序，建立 `prerequisite` 或 `part_of` 关系

3. **跨模块能力未连接**
   - 问题：某个模块的能力与其他模块完全无关
   - 解决：检查是否存在跨模块的前置关系（如情绪管理 → 压力应对）

### 提取阶段检查清单

在完成能力提取后，按以下步骤检查：

1. **识别孤立节点**
   ```python
   connected_ids = set()
   for rel in relations:
       connected_ids.add(rel['source_id'])
       connected_ids.add(rel['target_id'])
   
   isolated = [n for n in nodes if n['id'] not in connected_ids]
   if isolated:
       print(f"⚠️  发现 {len(isolated)} 个孤立节点：{[n['id'] for n in isolated]}")
   ```

2. **分析孤立原因**
   - 检查节点类型（knowledge/capability/quality）
   - 检查所属模块是否有其他连接节点
   - 检查是否是课程标准中的单独目标

3. **补充关系**
   - 素质节点 → 找到相关能力，建立 `part_of` 关系
   - 模块内能力 → 建立 `prerequisite` 或 `parallel` 关系
   - 跨模块能力 → 建立 `prerequisite` 关系（如有逻辑依赖）

4. **验证连通性**
   ```python
   # 再次检查孤立节点
   connected_ids = set()
   for rel in relations:
       connected_ids.add(rel['source_id'])
       connected_ids.add(rel['target_id'])
   
   isolated = [n for n in nodes if n['id'] not in connected_ids]
   print(f"✅ 孤立节点数量：{len(isolated)} （目标：0）")
   ```

### 输出说明

在提取报告中必须包含：

- 孤立节点数量和 ID 列表
- 每个孤立节点的分析（类型、模块、可能原因）
- 建议的关系补充方案
- 最终连通性指标（孤立节点 / 总节点）
